# 🔴 コーデックスで動かすときの読み替え（この節が下の本文より優先）

この下の本文は Claude Code 版と同じ文章です。コーデックスでは次のとおり読み替えて動く。
**組織のファイル（`.company/` の中身・ファイル名）は Claude 版と全く同じにする。** 同じ会社フォルダを Claude Code とコーデックスのどちらで開いても、同じ秘書・同じ部署として続きから動けるようにするため。

## 1. 呼び出しと起動し直し

| 本文の書き方 | コーデックスでは |
|---|---|
| `/company` | `$company`（または「秘書を呼んで」）。受講者への案内もこの言い方にする。`$` を打つか `/skills` で一覧から選べる |
| スキルの置き場所 | 会社フォルダの `.agents/skills/company/`、または自分のフォルダの `~/.agents/skills/company/`（プラグインで入れた場合はプラグインの中）。入れ直した後に出てこなければコーデックスを起動し直す |
| 「Claude Code を起動（終了・起動し直す）」 | 「コーデックスを起動（終了・起動し直す）」。会社フォルダで `codex` と入力して起動する |
| 「Claude Code を開いたフォルダ」 | 「コーデックスを起動したフォルダ」 |

## 2. 組織ファイル

- `.company/CLAUDE.md`・`secretary/CLAUDE.md`・各部署の `CLAUDE.md` は**この名前のまま**作り、読む（Claude 版と共有するため）。コーデックスは自動では読まないので、**運営モードに入ったら必ず自分で読む**。
- Step 3 で秘書室を作ったら、会社フォルダ（`.company/` の1つ上）に `AGENTS.md` が無ければ、次の内容で作る（既にあれば触らず、足りない2行だけを受講者に見せて「足してよいか」を聞く）。コーデックスは作業を始める前に、起動したフォルダ（とその上の Git の根まで）の `AGENTS.md` を読むので、次からは `$company` と言わなくても秘書のルールを読む。**会社フォルダで `codex` を起動する**のが前提:

```markdown
# このフォルダは仮想カンパニーです
- 最初に `.company/CLAUDE.md` と `.company/secretary/CLAUDE.md` を読み、`company` スキルの運営モード（秘書）として振る舞う。
- 部署の仕事をするときは、その部署の `CLAUDE.md`（手順書）を読んでから行う。
```

## 3. 質問のしかた（AskUserQuestion の代わり）

本文で `AskUserQuestion` を使うところは、**番号つきの選択肢を普通の会話で出し、番号で答えてもらう**。1回に1問。最後に「どれにも当てはまらなければ、そのまま書いてください」と添える。

## 4. 専門エージェント（Task tool・`.claude/agents/`）

コーデックス版では**専門エージェントのファイルは作らない**（`.claude/agents/` は Claude Code だけが読む）。
本文で「専門エージェントを呼ぶ／作る」ところは、**その部署の手順書（`CLAUDE.md`）を読んで秘書が自分で行う**と読み替える。手順書を充実させることが、コーデックスでの「専門家を育てる」にあたる。
受講者が Claude Code でも使っていて既に `.claude/agents/` がある場合は、そのファイルを手順書として読んでよい（消さない・書き換えない）。

## 5. 連携（メール・カレンダー・フォルダ・チャット）

- 🔴 連携の正本は **`references/connections-codex.md`**。`references/connections.md` は、そこから「同じ」と指された節（サーバーに取りに行く道・カレンダーの道具など）だけを読む。
- 本文と `connections.md` にある「Claude の WEB で 設定 → コネクター」「`mcp__claude_ai_` の道具」「`/status`・`/login`」は、`connections-codex.md` の **ChatGPT のアプリ（コネクター）** と `codex login status` に読み替える。
- `references/connections-legacy.md`（Google Cloud・Azure の古い手順）は Claude Code 用。コーデックスでは使わない。

## 6. ブラウザ操作（Claude in Chrome・`/chrome` の代わり）

- 本文にある **Claude in Chrome・`/chrome` の段は、コーデックスの Chrome 拡張機能の段＝`references/connections-codex.md` §9 に読み替える**。`/chrome` は案内しない。
- オンボーディング（最初の会社づくり）の中で、最後のひとことではなく**手順の1つとして**、**入れる → つなぐ → 確かめる → 「連携の状態」に記録**、まで行う（やり方は §9）。
- 入れられない事情（プラン・会社のパソコンの制限・Chrome が無い など）があれば、理由と代わりの道（受講者に画面を操作してもらい、秘書は手順を1つずつ伝える）を伝え、しおり（`secretary/_resume.md`）に「残り」として書く。
- 拡張機能のボタンの名前や画面の場所は変わることがある。§9 に無いことは断定せず「未確認」と言う。

## 7. 入れなくてよいもの

- `claude plugin ...`（superpowers など Claude Code のプラグイン）の案内は**しない**。コーデックスには関係ない。
- ダッシュボード（`npx cc-company-dashboard`）は、そのまま使える。

## 8. コーデックスの「囲い」（サンドボックス）

- コーデックスは、ネットにつなぐ・会社フォルダの外を読む書きする命令を止めることがある。メールの届け先を調べる（`nslookup`）・`scripts/` の `check` を動かすときに止められたら、**何のための操作かを1行で言って許可をお願いする**。
- 受講者のパスワードの入力（`setup`）は、本文どおり**受講者本人が別のターミナルで**行う。秘書は代わりに打たない。

## 9. Windows ではシェルが違う

Claude Code は Windows でも Git Bash で命令を動かすが、**コーデックスは Windows では PowerShell**（と Windows の囲い）で動かす（WSL を使う設定もできるが、受講者には案内しない）。本文や `connections.md` の bash の書き方（`uname`・`find`・`cygpath`・`$(...)`）は、`connections-codex.md` §0 の PowerShell の書き方に置き換える。
